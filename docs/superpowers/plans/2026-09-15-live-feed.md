# Live Feed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Live tab — a public, platform-wide feed of every match in progress right now, tournament and quick play merged.

**Architecture:** Two partial indexes make "what is in progress" a cheap lookup instead of a collection scan. A new service merges both collections, shapes each row through the sport's existing optional `summariseForFeed` adapter, caps the list and caches it for 15 seconds. `GET /live` is public. Mobile consumes it through a local-state hook, not a Redux slice.

**Tech Stack:** Express + TypeScript (server, 4-space indent), Mongoose, Redis, vitest + supertest + `mongodb-memory-server`; React Native 0.86.3 / Expo SDK 57 / TypeScript strict (mobile, 2-space indent), jest + `@testing-library/react-native` + `axios-mock-adapter`.

**Spec:** `docs/superpowers/specs/2026-09-15-explore-and-live-design.md` (**umbrella** repo, one level above `mobile/` and `server/`). Read §4 (privacy), §5 (Live server) and §7 (mobile) before starting.

**This is the first of two plans.** Explore is a separate plan and is not built here. This plan owns the `NAV_SLOTS` change for **both** slots' infrastructure but flips **only** Live to a real route.

- **Mobile gates:** `npx jest` (baseline **951 passing / 90 suites**), `npx tsc --noEmit` (**baseline ZERO**), `npx expo config --json` (exit 0).

- **Server layering is binding** (`codingPattenAndRule.md`): Route → Validator → Controller → Service → Repository → Model. **No Mongoose outside the repository.** Controllers hold no logic. Use `asyncHandler` for async controllers and `createResponse`/`SuccessResponse` for responses.

### Task 1: Partial indexes and the two live queries

The data layer. Both collections gain an index that contains **only live rows**, and the repositories gain one method each.

**Files:**
- Modify: `server/src/models/match.model.ts` (index block, near line 349)
- Modify: `server/src/models/quickMatch.model.ts` (index block, near line 69)
- Modify: `server/src/repository/match.repository.ts`
- Modify: `server/src/repository/quickMatch.repository.ts`
- Test: `server/test/liveFeedRepository.test.ts` (create)

**Interfaces:**
- Consumes: nothing.
- Produces:
  - `matchRepository.findLive(limit: number): Promise<IMatch[]>` — with `tournamentId` and `categoryId` **populated to `{ _id, name }`**, because the feed row is headed by the tournament's name.
  - `quickMatchRepository.findLive(limit: number): Promise<IQuickMatch[]>`
  Both return newest-first by `createdAt`.

**Why partial, and why this is safe** (spec §5.2): `matchSchema.index({ tournamentId, categoryId, status })` has `status` **third**, so querying status alone cannot use it. A plain `{status: 1}` index would work but is low-cardinality. A **partial** index holds only in-progress rows — small and selective. MongoDB updates an index only when an **indexed field changes**, and ball-by-ball scoring writes `cricketLiveState`/`gameScores`, **never `status`** — so this costs nothing on the hot scoring path. Partial indexes are already the house pattern (`tournament_bracket_slot_unique`).

In `server/src/repository/match.repository.ts`, inside the repository class:

```typescript
    /** In-progress tournament matches, newest first. Served by the
     *  `live_tournament_matches` partial index.
     *
     *  Populates the tournament and category names because the feed row is
     *  headed by the tournament ("Kria Smash Cup"), not by an id. Two
     *  `.populate()`s on a list capped at 40 is one extra lookup each; the
     *  alternative is the service issuing its own queries, which would put
     *  Mongoose outside the repository and break the layering rule. */
    async findLive(limit: number): Promise<IMatch[]> {
        return Match.find({ status: 'in_progress' })
            .sort({ createdAt: -1 })
            .limit(limit)
            .populate('tournamentId', 'name')
            .populate('categoryId', 'name')
            .lean<IMatch[]>()
            .exec();
    }
```

In `server/src/repository/quickMatch.repository.ts`:

```typescript
    /** Live quick matches, newest first. Served by the `live_quick_matches`
     *  partial index. */
    async findLive(limit: number): Promise<IQuickMatch[]> {
        return QuickMatch.find({ status: 'live' })
            .sort({ createdAt: -1 })
            .limit(limit)
            .lean<IQuickMatch[]>()
            .exec();
    }
```

### Task 2: The feed service

Merge both collections into one shaped, capped list and cache it.

**Files:**
- Create: `server/src/services/liveFeed.service.ts`
- Modify: `server/src/services/cache/entities.ts`

**Interfaces:**
- Consumes:
  - `matchRepository.findLive(limit): Promise<Array<{ sport: string; match: IMatch }>>` — **note the wrapper.** Per-sport match documents carry no sport field (the collection *is* the sport), so the repository preserves it from the registry iteration. Read the sport off the **wrapper**, never off the document.
  - `quickMatchRepository.findLive(limit): Promise<IQuickMatch[]>` — quick matches **do** carry `sport` on the document, so this one is unwrapped.
- Produces:
  - `export const LIVE_FEED_CAP = 40;`
  - `export type LiveItem` — the discriminated union below.
  - `liveFeedService.getFeed(): Promise<SuccessResponse<{ total: number; items: LiveItem[] }>>`
  - `liveFeedCacheManager` exported from `cache/entities.ts`.

**Reuse the sport adapter, do not reimplement scoring.** `summariseForFeed(match): FeedSummary | null` already exists on both sport adapters and returns `{ title, scoreline? }`. It is **optional on the contract on purpose** (PROJECT-STATE §9) so a new sport can run matches before it has an opinion on how its scores read. **A sport without it yields a thin row — never skip the match and never make the method required.** `careerStats.service.ts:376` is the call pattern to copy.

```typescript
import { matchRepository } from '../repository/match.repository';
import { quickMatchRepository } from '../repository/quickMatch.repository';
import { sportRegistry } from '../sports/registry';
import { SportKey } from '../sports/_contracts/SportKey';
import { SuccessResponse } from '../utils/response.util';
import { liveFeedCacheManager } from './cache/entities';
import logger from '../utils/logger';

/**
 * Capped, not paginated. The tournament list's rule applies: a cap the UI
 * never promises past is honest, and real paging is a feature nobody has
 * asked for. Forty rows is more live matches than this platform has had at
 * once, so the cap is a ceiling rather than a limit today.
 */
export const LIVE_FEED_CAP = 40;

interface LiveItemBase {
    matchId: string;
    sport: string;
    /** From the sport adapter: "Kohli vs Rahul". Absent-safe. */
    title?: string;
    /** From the sport adapter: "21-15, 21-18". Absent when it has no opinion. */
    scoreline?: string;
    startedAt: string;
}

export type LiveItem =
    | (LiveItemBase & {
        kind: 'tournament';
        tournamentId: string;
        /** The row's heading. The artboard leads with this, not with an id. */
        tournamentName?: string;
        categoryId: string;
        categoryName?: string;
        round?: string;
    })
    | (LiveItemBase & { kind: 'quick' });

export interface LiveFeed {
    total: number;
    items: LiveItem[];
}

const CACHE_KEY = { scope: 'all' };

export class LiveFeedService {
    /**
     * The sport's own feed summariser, when it has one.
     *
     * `summariseForFeed` is optional on the MatchAdapter contract on purpose,
     * so a new sport can run real matches before it has an opinion on how its
     * scores read. A sport without it yields a row with no title and no
     * scoreline — thin, but present. Never skip the match, and never make the
     * method required: that would gate scoring on a display concern.
     */
    private _summarise(sport: string, match: unknown): { title?: string; scoreline?: string } {
        const sportModule = sportRegistry.get(sport as SportKey);
        const summarise = sportModule?.matchAdapter.summariseForFeed;
        if (!sportModule || !summarise) return {};
        const summary = summarise.call(sportModule.matchAdapter, match);
        return summary ? { title: summary.title, scoreline: summary.scoreline } : {};
    }

    async getFeed(): Promise<SuccessResponse<LiveFeed>> {
        const cached = await liveFeedCacheManager.get(CACHE_KEY) as LiveFeed | null;
        if (cached) return new SuccessResponse('Live matches.', cached);

        const [tournamentEntries, quickMatches] = await Promise.all([
            matchRepository.findLive(LIVE_FEED_CAP),
            quickMatchRepository.findLive(LIVE_FEED_CAP),
        ]);

        const items: LiveItem[] = [
            // The sport comes off the WRAPPER, not the document. A tournament
            // match document has no sport field at all — its collection is its
            // sport — so reading `match.sport` here yields undefined, every
            // adapter lookup misses, and every row silently loses its title
            // and scoreline while the tests still pass.
            ...tournamentEntries.map(({ sport, match }): LiveItem => {
                // `.populate()` turns these into documents; a match whose
                // tournament was deleted leaves the raw id. Read defensively
                // rather than assuming the join resolved — the name is
                // optional on the type for exactly this reason.
                const tournament = match.tournamentId as unknown as { _id?: unknown; name?: string };
                const category = match.categoryId as unknown as { _id?: unknown; name?: string };
                return {
                    kind: 'tournament',
                    matchId: String(match._id),
                    sport,
                    tournamentId: String(tournament?._id ?? match.tournamentId),
                    tournamentName: tournament?.name,
                    categoryId: String(category?._id ?? match.categoryId),
                    categoryName: category?.name,
                    round: match.bracketRound ? String(match.bracketRound) : undefined,
                    startedAt: new Date(match.createdAt).toISOString(),
                    ...this._summarise(sport, match),
                };
            }),
            // Built field by field, never by spreading the document. A spread
            // would carry joinCode into a public response the moment the
            // schema grows — the privacy contract in spec §4 has to be
            // structural, not a deletion someone remembers to keep doing.
            ...quickMatches.map((match): LiveItem => ({
                kind: 'quick',
                matchId: String(match._id),
                sport: String(match.sport),
                startedAt: new Date(match.createdAt).toISOString(),
                ...this._summarise(String(match.sport), match),
            })),
        ]
            .sort((a, b) => b.startedAt.localeCompare(a.startedAt))
            .slice(0, LIVE_FEED_CAP);

        const feed: LiveFeed = { total: items.length, items };

        try {
            await liveFeedCacheManager.set(CACHE_KEY, feed);
        } catch (err) {
            // A Redis outage must not take the feed down with it. The query
            // already succeeded; serving it uncached is the correct fallback.
            logger.error(`liveFeed cache write failed: ${String(err)}`);
        }

        return new SuccessResponse('Live matches.', feed);
    }
}

export const liveFeedService = new LiveFeedService();
```

```typescript
import API from './axios';
import { unwrap } from './unwrap';

interface LiveItemBase {
  matchId: string;
  sport: string;
  title?: string;
  scoreline?: string;
  startedAt: string;
}

/**
 * Mirrors the server's union. `joinCode` is deliberately absent and must stay
 * absent: the feed is public, and the six-character code is what lets someone
 * JOIN a quick match rather than merely watch it.
 */
export type LiveItem =
  | (LiveItemBase & {
      kind: 'tournament';
      tournamentId: string;
      /** The row's heading. Optional: a match whose tournament was deleted
       *  still appears, headed by its sport instead of crashing the list. */
      tournamentName?: string;
      categoryId: string;
      categoryName?: string;
      round?: string;
    })
  | (LiveItemBase & { kind: 'quick' });

export interface LiveFeed {
  total: number;
  items: LiveItem[];
}

export async function fetchLiveFeed(): Promise<LiveFeed> {
  const payload = unwrap<LiveFeed | null>(await API.get('/live'));
  return payload ?? { total: 0, items: [] };
}
```

- [ ] **Step 4: Write the hook**

Create `mobile/src/lib/useLiveFeed.ts`:

```typescript
import { useCallback, useEffect, useState } from 'react';
import { fetchLiveFeed, type LiveItem } from '@/api/live';

export function useLiveFeed() {
  const [items, setItems] = useState<LiveItem[]>([]);
  const [total, setTotal] = useState(0);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  const load = useCallback(async () => {
    setLoading(true);
    try {
      const feed = await fetchLiveFeed();
      setItems(feed.items);
      setTotal(feed.total);
      setError(null);
    } catch {
      // An empty evening and a dead server must not look the same on the
      // screen, so a failure clears the list AND sets an error rather than
      // leaving stale rows that claim to be live.
      setItems([]);
      setTotal(0);
      setError('Could not load live matches.');
    } finally {
      setLoading(false);
    }
  }, []);

  useEffect(() => { void load(); }, [load]);

  return { items, total, loading, error, refresh: load };
}
```
