Create `server/src/utils/escapeForRegex.ts`:

```typescript
/**
 * Escape a user-supplied string for literal use inside a `RegExp`.
 *
 * This is a security control, not a convenience. Unescaped user input in a
 * regular expression is a denial-of-service vector: a pattern like `(a+)+$`
 * backtracks catastrophically and can hang the event loop for every request,
 * not just the attacker's. It also silently changes results — a user typing
 * `.` would otherwise match every character rather than a full stop.
 *
 * Shared deliberately rather than copied. It was a file-local const in
 * player.repository.ts; a second copy of a security control is how one copy
 * eventually drifts from the other.
 */
export const escapeForRegex = (input: string): string => input.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
```

In `server/src/repository/player.repository.ts`, delete the local const at line 6 and import the shared one. **Do not change the anchoring or any other behaviour of `searchByNamePrefix`** — this step is a move, and the existing player-search tests must stay green untouched.

**Do NOT use `fetchPublicTournaments` from the Redux tournament slice.** It writes into a **single shared** `publicTournaments` slot that the Home screen reads. A search dispatched from Explore would silently re-filter Home's tournament strip, and the user would find Home changed with no explanation. `CLAUDE.md` is also explicit that feature data here uses local-state hooks and that a slice for a screen-scoped GET is over-building. Explore gets its own API module and its own hook, and touches no slice.

**Debounce, and guard the race.** A search box fires on every keystroke. Debounce at **300ms**, and use the **same epoch-ref guard `src/lib/useLiveFeed.ts` already uses** — read it and match it. With a debounced search, out-of-order responses are not a theoretical edge case: a short query returning slowly after a longer one is routine, and without the guard the user sees results for text they have already replaced.

**`searchPlayers` already handles the 3-character minimum**, resolving the server's 422 to an empty list while rethrowing everything else. Do not re-implement that; give the tournament side the same shape, and let the hook skip firing at all below 3 characters.

Create `mobile/src/api/tournaments.ts`:

```typescript
import API from './axios';
import { unwrap } from './unwrap';
import { toQuery, type Filters } from '@/lib/tournamentFilters';

export interface TournamentHit {
  _id: string;
  name: string;
  sport: string;
  status: string;
  venue?: { city?: string };
}

interface TournamentListPayload {
  tournaments: TournamentHit[];
  pagination?: { total?: number };
}

/**
 * Deliberately NOT the Redux `fetchPublicTournaments` thunk. That writes into
 * a single shared `publicTournaments` slot the Home screen reads, so a search
 * typed here would silently re-filter Home's tournament strip and the user
 * would find Home changed with no explanation.
 *
 * A search 422s below three characters the same way player search does, and
 * resolves to an empty list rather than surfacing an error the user cannot act
 * on. Anything else rethrows — a dead server must not look like no results.
 */
export async function searchTournaments(q: string, filters?: Filters): Promise<TournamentHit[]> {
  try {
    const params = { ...(filters ? toQuery(filters) : {}), q };
    const payload = unwrap<TournamentListPayload | null>(await API.get('/tournament', { params }));
    return payload?.tournaments ?? [];
  } catch (err) {
    const status = (err as { response?: { status?: number } })?.response?.status;
    if (status === 422) return [];
    throw err;
  }
}
```

`toQuery` is verified: `toQuery(f: Filters): { sport?: string; city?: string; status?: string }` — it drops any facet still set to `ALL`, so spreading it and adding `q` is exactly right.
